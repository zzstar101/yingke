# 应刻 · Yingke

**校园大小事，应刻掌握。**

面向广州应用科技学院学生的校园服务聚合客户端。优先开发 **iOS 原生版（Swift + SwiftUI）**，后续开发 **Android 原生版（Kotlin + Jetpack Compose）**。

> iOS 原生首版提供免登录首页和独立校园账号。强智教务已接入官方网页登录，并提供课表、成绩、考试安排和培养方案的只读入口。应用内的真实账号端到端验证待完成。本项目由第三方独立开发。

## 运行 iOS 首版

使用 Xcode 16 或更新版本打开工程，选择 `Yingke` scheme 和 iOS 18 或更新版本的模拟器，然后运行。设计参考和命令行测试见首版说明。

## 已确认的产品范围

**账号按需绑定，第一阶段不设置应用自有账号，不做云端账号同步。** 各校园平台独立维护凭据和会话，优先本地存储。

| 系统 | 计划接入的功能 | 账号/认证 |
| --- | --- | --- |
| 学习通 | 课程、作业、考试、图书馆、图书检索、智慧微空间预约 | 学习通账号；不同模块是否共享会话待验证 |
| 教务系统（强智） | 课表、成绩、考试安排、培养方案 | 独立教务账号，非学校统一认证 |
| 校园统一身份认证 | 流程审批、实验室预约、校园 WebVPN | 独立统一认证账号 |
| 到梦空间 | 活动浏览和报名、现场静态二维码签到、二课学分、热门/最新活动、已关注部落及其新活动通知 | 独立到梦空间账号 |

**暂缓**：水电费（微信网页 OAuth，现有站点仅 HTTP，原生登录集成与安全性待研究）。

**不在当前范围**：校园网认证、校园邮箱、校园论坛、APP 自有账号、鱼小应账号复用、云端凭据同步。未来可重新评估，不默认纳入初版。

## 开发原则

1. **原生优先**：SwiftUI 与 Compose 分别适配 iOS / Android，业务概念和 API 契约保持一致，不将 UI 逐行翻译。
2. **按需授权**：打开相应模块时再提示绑定对应平台，不强制一次登录所有系统。
3. **本地优先**：凭据、Cookie、敏感缓存默认只保存在本机；需要推送时再评估最小化服务端。
4. **故障隔离**：单一学校平台不可用不影响其他模块，仍可显示最后成功同步的缓存。
5. **不夸大可用性**：区分“已验证接口”“页面可访问”“未经验证”“尚未调研”。
6. **保护用户数据**：不在仓库、Issue、日志或测试样本中提交真实校园账号、密码、会话 Cookie 或学籍隐私。
