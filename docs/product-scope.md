# 产品需求与范围（2026-11-18）

> 状态：需求基线 V0.1。本文记录已经确认的用户意图，不等于接口已实现或可用性已经验证。暂不确定 MVP、开发里程碑或最终导航设计。

## 1. 产品定位

应刻（Yingke）是面向广州应用科技学院学生的第三方校园服务聚合应用。聚合多个学校系统的数据和操作入口，尽量使用原生界面，不要求用户在初次启动时绑定所有平台。

**开发顺序**：iOS（Swift / SwiftUI）优先，后续 Android（Kotlin / Jetpack Compose），两端原生实现。

**第一阶段原则**：
- 不做应刻自有账号、注册、学生认证或校园论坛。
- 不复用鱼小应账号，也不设计自有账号后端。
- 学校系统按需绑定；多套学校账号彼此独立。
- 凭据和校园数据本地优先，不做跨设备云同步。
- 不因为某个服务故障而阻塞整个 APP；提供缓存和明确的异常提示。
- 暂不决定最终信息架构、导航栏、功能优先级。

## 2. 功能清单

### 2.1 学习通（独立账号）

- 课程
- 作业
- 考试
- 图书馆
- 图书检索
- 智慧微空间预约

以上功能均使用学习通账号体系；它们是否复用同一个 Token / Cookie / 子系统会话 **待验证**。

**明确不在当前范围**：课程签到、学习通成绩、课程通知、资料下载等额外功能。不要自行扩展需求。

### 2.2 强智教务系统（独立账号）

- 课程表（含不同学期/周次）
- 成绩查询
- 考试安排
- 培养方案

已有真实会话下的接口调研成果，见 [强智教务接口研究](research/qz-academic.md)。

学籍页面等接口虽然已有调研结果，目前仍归为**技术参考**，不能据此自动扩充产品范围。

### 2.3 学校统一身份认证（独立账号）

- 流程审批
- 实验室预约
- 校园 WebVPN

目前只确认这些服务走统一身份认证。新的服务等实际发现后再补。

### 2.4 到梦空间（独立账号）

- 浏览活动详情与报名
- 在 APP 内完成官方报名流程
- 在 APP 内扫描活动现场展示的**静态二维码**完成签到
- 查询第二课堂学分
- 热门活动展示
- 最新活动展示
- 自动同步当前到梦空间账号的**已关注部落**
- 已关注部落发布新活动时，尽可能及时发送 iOS **系统通知**

**边界**：不做在应刻中关注或取消关注部落的写操作；不做个性化活动推荐；签到应遵守官方校验要求，不绕过活动现场验证。

报名、签到、同步关注关系等接口仍待调研。“APP 内完成”是产品目标，不代表已经确认技术可行。

### 2.5 暂缓和排除

| 系统/功能 | 当前决策 | 原因 |
| --- | --- | --- |
| 水电费 | 暂缓接入 | 微信网页 OAuth；原生授权机制未验证；既有网站仅 HTTP |
| 校园网 | 当前不做 | 已明确排除 |
| 校园邮箱 | 当前不做 | 依赖企业微信/网页版；未开放 IMAP/POP3 |
| APP 自有账号、论坛、社交 | 以后再说 | 当前聚焦校园服务聚合 |
| 云端同步校园凭据 | 当前不做 | 本地优先；降低安全复杂度 |
| 个性化活动推荐 | 不做 | 只做热门与最新 |

## 3. 关键交互约束

- 用户首次打开 APP 不必先登录任何学校账号。
- 使用某一功能时若尚未绑定相应平台，显示该平台的绑定入口。
- 已绑定平台的会话失效，只影响该平台；其他平台正常使用。
- 不得把“学校统一认证”与“教务系统”误认为同一套密码或共用登录态。
- 活动提醒的**及时性**需要单独研究服务器/APNs，不能把 iOS 后台刷新当作实时方案。
- 每个系统的网络、解析、授权能力以实测为准；不可用时提供明确说明。

## 4. 需求变更规则

新增功能须明确其来源系统、用户可见行为，以及是否涉及后台同步或写操作。把“用户确认要做”与“接口验证可做”分开记录，避免在开发阶段混淆。
