# 到梦空间：关注部落新活动通知

> 状态：产品目标已确认，技术可行性待验证。

## 已确认需求

- 账号按需绑定，连接到梦空间后**自动读取已关注的部落**。
- 在应刻中只展示关注结果，不做关注/取消关注的写操作。
- 活动栏目展示热门与最新活动，不做个性化推荐。
- 关注部落发布新活动时，**尽可能实时**发出 iOS 系统通知。
- 活动报名、现场静态二维码签到希望在 APP 内完成，遵守官方流程。

## 为什么仅靠本地 iOS 客户端无法保证实时

iOS 后台刷新由系统调度，执行频率不可保证；被系统终止的 APP 也不能持续轮询。若要在 APP 未打开时尽可能及时收到新活动，原则上需要：
1. 合法可靠的新活动数据源。
2. 某个运行中的服务持续或定期检测变化。
3. 通过 APNs 向已授权的设备发送通知。

APNs 具备系统级投递能力，但**不承诺固定秒数延迟**。业务接口本身延迟或轮询频率都会影响最终通知时效。

## 推荐的最小服务端边界（条件成立后才实施）

手机本地：
- 保留到梦空间账号、密码/Token 和业务会话。
- 登录成功后读取用户已关注的部落 ID。
- 用户允许系统通知后向轻量服务登记设备推送 Token、订阅部落 ID 与必要的过期/撤销信息。
- 更新关注列表时增量更新订阅，退出登录/解绑时注销订阅。

服务端：
- **不存储到梦空间用户名、密码、Cookie 或第三方会话令牌**。
- 仅在允许获取活动数据的前提下，获取部落的新活动信息。
- 以部落和活动 ID 去重，向订阅该部落的设备发 APNs 通知。
- 支持过期设备 Token 清理、通知频率控制和最小化日志。

## 关键阻塞项

1. 到梦空间是否存在可合法读取的部落活动信息源？是否公开可查，还是必须持有个人登录态？
2. 是否能获取稳定的已关注部落标识、活动唯一 ID、发布时间？
3. 最新活动数据能否以足够低延迟获取？学校平台有无限流及授权要求？
4. 在纯本地身份、无应刻自有账号的前提下，如何登记、更新、撤销设备订阅，并防止他人伪造订阅？
5. 如何处理用户撤销通知权限、解绑到梦空间、换设备及 APNs token 变更？

**如果活动数据必须使用用户个人凭据才能获取，不能默认把第三方凭据上传服务器**。需要重新评估是否有官方或公共数据源；否则降低通知时效预期，并明确告知用户技术限制。

## 当前不做

- 自有用户注册/登录后端
- 将到梦空间账号托管到服务端
- 在 APP 内关注/取消关注部落
- 个性化活动推荐
- 绕过官方活动报名或二维码签到验证
